================================================================================
1. OBJECTIVE & DESIGN
================================================================================
Build a directed, weighted pass-network graph per (match, team) from
pass_network_edges, compute graph-theoretic cohesion metrics (density,
clustering coefficient, centrality, betweenness, PageRank), and use them
to predict goals scored. Network topology alone is a weak predictor of
outcome, so the feature set is deliberately widened with the strongest
known contextual predictors of goals (team xG, xG conceded, home
advantage, opponent quality) to make the model honestly useful rather
than reporting an inflated graph-only R^2.

This is a graph analysis + regression hybrid, not a pure GNN/embedding
model — graphs are summarized into 12 scalar features per team-match,
fed into Ridge and Gradient Boosting regressors.

================================================================================
2. FEATURES USED
================================================================================

GRAPH FEATURES (12) — built per (match_id, team_id) directed pass graph:
  network_density          undirected density of the pass graph
  clustering_coefficient   average local clustering coefficient (triadic closure)
  mean_in_centrality        mean in-degree centrality across players
  mean_out_centrality       mean out-degree centrality across players
  mean_betweenness          mean betweenness centrality (weighted by pass_count)
  max_betweenness           max betweenness — most "indispensable" passer
  mean_pagerank             mean PageRank (weighted)
  max_pagerank              max PageRank — most influential node
  n_nodes                   players involved in the pass network
  n_edges                   distinct passer->receiver connections
  total_passes              sum of pass_count across all edges
  pass_per_edge             total_passes / n_edges (link reinforcement)

CONTEXT FEATURES (4) — appended because graph topology alone explains very
little variance in goals (confirmed below, Section 4):
  team_xg            sum of player xG for the team in the match
  team_xga           opponent's team_xg in the same match (xG against)
  is_home            1 if playing at home
  opponent_quality   opponent's season-to-date points-per-game, expanding
                     mean shifted by 1 match to exclude the current result
                     (prevents leakage), filled with league average when
                     no prior matches exist

MODEL_FEATURES = GRAPH_FEATURES + CONTEXT_FEATURES  (16 total)

Target: goals scored by the team in that match (regression, not classification).

================================================================================
3. SUCCESSFUL TECHNIQUES (what fixed real problems)
================================================================================

(a) GroupKFold by match_id, not shuffled K-fold
    Both team-rows of the same match share match-level signal (their xG
    values come from the same shots, the score is jointly determined).
    A shuffled split would let the home-team row leak into training while
    the away-team row of the same match sits in test, inflating R^2.
    GroupKFold(n_splits=5) keyed on match_id guarantees no match straddles
    the train/test boundary. (models/eval_utils.py:grouped_cv)

(b) Pipeline-wrapped StandardScaler inside cross-validation
    The original implementation fit the scaler on the full dataset before
    CV, leaking test-fold statistics into the scaler. Wrapping
    StandardScaler + estimator in an sklearn Pipeline means the scaler is
    refit on training folds only inside each CV split. Persisted artifacts
    (scaler.pkl + estimator.pkl) are still produced separately afterward
    so the serving path in api_server.py is unchanged.

(c) Out-of-time holdout on a held-out season (2022, FIFA World Cup)
    The strictest generalization check available in this data: train on
    every other season, test once on a season the model has never seen,
    with genuinely different teams/players than the dominant 2015/16
    La Liga slice. This is far more honest than another in-distribution
    CV fold.

(d) Widening beyond "pure" graph features
    Graph-only features hit R^2 ~ 0.04 (GBR) / 0.05 (Ridge) — confirmed
    in this diagnostics run (Section 4). Rather than overselling a graph
    model that barely beats a mean predictor, the feature set explicitly
    includes team_xg/team_xga/is_home/opponent_quality, which are computed
    with leakage controls (opponent_quality is shifted before merge).

(e) opponent_quality computed via expanding mean, shifted by 1
    Avoids using the current match's result to estimate the opponent's
    quality at the time of the match — a common leakage trap in football
    analytics pipelines (load_team_context in model2_team_cohesion.py).

================================================================================
4. KEY FINDINGS
================================================================================

1. Pass-network topology alone is a weak predictor of goals.
   Graph-only feature set (12 features): GBR R^2 = 0.024 +/- 0.022,
   Ridge R^2 = 0.046 +/- 0.021 (GroupKFold by match). This matches the
   code's own stated prior ("R2 ~ 0.05-0.09") closely — cohesion
   metrics capture HOW a team passes, not whether those passes translate
   to goals.

2. Context features alone do almost all of the work.
   Context-only feature set (4 features: team_xg, team_xga, is_home,
   opponent_quality): GBR R^2 = 0.324 +/- 0.011, Ridge R^2 = 0.310 +/- 0.017.
   team_xg in isolation carries Spearman rho = +0.544 with goals (by far
   the strongest univariate signal of any feature, p < 1e-300).

3. Combining graph + context gives a real, if modest, lift over context alone.
   Full 16-feature set: GBR R^2 = 0.340 +/- 0.012, Ridge R^2 = 0.317 +/- 0.018.
   That's +0.32 R^2 over graph-only, but only +0.02 R^2 over
   context-only — graph features are a genuine but secondary signal once
   xG-based context is present, not a redundant one (GBR aggregate feature
   importance: 81.5% context / 18.5% graph — graph features are not zero).

4. total_passes and pass_per_edge carry real incremental signal.
   Among graph features, total_passes (Spearman rho=+0.101) and
   pass_per_edge (rho=+0.124) have the strongest univariate correlation
   with goals — teams that complete more passes and reinforce specific
   passing lanes more heavily tend to score more, independent of xG.
   They also rank #3 and #12 in GBR importance and dominate the Ridge
   standardized coefficients (+0.774 and -0.621 respectively — the sign
   flip indicates a useful interaction/multicollinearity effect with
   n_edges/n_nodes rather than a contradiction).

5. Pure centrality/connectivity metrics (PageRank, in/out-degree
   centrality, clustering coefficient) show almost no marginal signal.
   mean_pagerank (rho=-0.023), mean_in/out_centrality (rho=+0.009),
   clustering_coefficient (rho=-0.006) are statistically indistinguishable
   from noise at the team-match level. They describe network *shape*, which
   apparently does not vary enough match-to-match (mean clustering
   coefficient = 0.813, std = 0.054 — a tight, low-variance distribution)
   to discriminate outcomes.

6. Severe multicollinearity exists within the graph feature block, as expected
   for graph-theoretic metrics derived from the same adjacency structure:
     mean_in_centrality <-> mean_out_centrality   rho=1.000 (mathematically
       near-identical for this pass-graph construction)
     total_passes <-> pass_per_edge               rho=0.947
     network_density <-> mean_in/out_centrality    rho=0.913
     mean_pagerank <-> n_nodes                     rho=0.822
     network_density <-> clustering_coefficient    rho=0.769
   This does not hurt the tree-based GBR, but it does destabilize the
   Ridge coefficients (the sign flips on total_passes/pass_per_edge above
   are a direct symptom) — coefficient magnitudes should not be read as
   independent causal effects without addressing this collinearity (e.g.
   dropping mean_out_centrality as a literal duplicate).

7. Model generalizes out-of-time, not just out-of-fold.
   GBR R^2 on the held-out 2022 World Cup season = 0.342 — almost
   identical to the in-distribution grouped-CV estimate (0.343). This is
   a strong result: 2022 is a different competition, different teams, and
   only 3.1% of the dataset, yet performance does not degrade. The model
   is not simply memorizing 2015/16 La Liga/Barcelona patterns.

8. Absolute error is large relative to the target's scale.
   GBR MAE = 0.781 goals, RMSE = 1.000 goals, against a target with mean
   1.330 and std 1.235 goals/team/match. The model explains real variance
   (R^2=0.34) but typical residual error is still nearly a full goal —
   appropriate for "directional/expected" framing, not for precise
   scoreline prediction.

9. is_home has small standalone signal (rho=+0.131) but contributes almost
   nothing in the full GBR model (0.2% importance) — its information is
   likely absorbed by opponent_quality and team_xg (home teams tend to
   generate more xG, which is already captured directly).

================================================================================
6. LIMITATIONS / WHAT THE NUMBERS DO NOT SAY
================================================================================
- R^2 ~ 0.34 means the model explains roughly a third of goal variance —
  useful as a directional/relative signal (e.g. team-vs-team comparison,
  cohesion trend tracking) but not a scoreline predictor.
- The headline R^2 is driven almost entirely by team_xg/team_xga, which are
  themselves derived from a separate xG model (models/model_xg.py) and from
  shots already taken in the match being predicted — i.e. this is closer to
  "given the chances created, did cohesion add anything" than a pre-match
  forecast. A true pre-match cohesion model would need to lag team_xg to a
  rolling pre-match average, similar to how opponent_quality is already lagged.
- 2015/2016 La Liga (heavily Barcelona-weighted) makes up 88.8% of the
  feature matrix (3,646 / 4,106 rows); the other 4 seasons are thin slices
  (102-128 rows each). The held-out-season check on 2022 is reassuring but
  is a single 128-row sample, not a robust multi-season average.
- Graph features' weak standalone signal could reflect genuine football
  reality (cohesion shapes process, not directly outcome) or a measurement
  ceiling (12 summary scalars discard most of the graph's structure — e.g.
  no sub-community/triangle-motif features, no positional weighting of
  centrality). Both explanations are consistent with the data and are not
  distinguished by this diagnostic.

7. OPTIMIZED MODEL (v2) — APPROACH USED & PERFORMANCE
================================================================================
Source code: models/model2_team_cohesion.py:run_optimized()  (run via
             `python -m models.model2_team_cohesion --optimize`)
Full report: artifacts/model2/model2_optimized_diagnostics.txt
Artifacts:   gbr_postmatch.pkl, scaler_postmatch.pkl, feature_columns_postmatch.json
             (separate from gbr.pkl/scaler.pkl above -- the v1 artifacts and
             api_server.py are untouched by this pipeline)

--- APPROACH USED ---

1. Engineered 12 additional graph features beyond the original 12: pass
   concentration (pass_entropy, pass_concentration_gini, max_edge_share,
   top_3_edge_share), hub dominance (hub_dominance = max/mean PageRank),
   reciprocity, per-player normalisation (weighted_density, passes_per_player,
   edges_per_player), centralization_index, largest_component_ratio, and
   modularity (community structure via greedy modularity on the undirected
   pass graph) -- compute_graph_features() now returns 24 keys total.

2. Ran a data-driven multicollinearity audit (Spearman |rho| > 0.90) over
   all 24 graph features instead of hand-picking which to drop. 10 were
   removed as near-duplicates (e.g. mean_out_centrality vs mean_in_centrality,
   rho=1.000; total_passes vs passes_per_player, rho=0.989). 14 survived --
   see the dropped-feature list in model2_optimized_diagnostics.txt section 1.

3. Compared 7 regression algorithms (Ridge, ElasticNet, RandomForest,
   ExtraTrees, GradientBoosting, HistGradientBoosting, XGBoost) under the
   same GroupKFold(5)-by-match protocol as v1, across 3 feature sets
   (graph-only, context-only, full) plus a mean-predictor baseline --
   28 model x feature-set combinations, each scored on R2/MAE/RMSE in one
   pass (eval_utils.grouped_cv_multi).

4. Tuned the top-2 baseline performers (GBR, ExtraTrees) with
   RandomizedSearchCV (20 random configs x 5-fold GroupKFold, scored on R2).

5. Validated generalisation the same way as v1 (held-out 2022) plus a new
   leave-one-season-out sweep (every season held out in turn, not just 2022)
   -- eval_utils.leave_one_season_out().

6. Computed both native feature importances and permutation importance
   (20 repeats) for the final tuned model, on top of the GBR-only
   feature_importances_ reported in Section 5 above.

A pre-match/forecast variant (rolling 5-match team history instead of this
match's own xG/graph features, zero current-match leakage) was also built
and evaluated: it explained only R2~0.08-0.11 of goal variance, far below
the postmatch/explanatory numbers below. It was removed from the shipped
pipeline by request to keep scope to the explanatory framing, but the
result is preserved here because it is the honest answer to "can this be
used as a forecast" -- no, not with this feature set.

  v2's in-distribution CV score improved slightly, but its out-of-time
  score on the genuinely unseen 2022 season is lower than v1's. The tuned
  model fits the dominant 2015/16 data a bit better at a small cost to
  generalisation on a different season/competition. This is reported
  rather than hidden: v2 is not an unambiguous upgrade over v1, it is a

  performance -- the real gain is the removed multicollinearity, the
  richer/justified feature set, and the explicit explanatory-vs-forecast
  framing, not a large R2 jump.
